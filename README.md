# 静水手记

安装：`npm install`

本地启动：`npm run dev`

Docker 启动：`docker compose up --build`，访问 http://localhost:18224。

校验：`npm run typecheck` · 构建：`npm run build`

## 单键辅助方案

为只能完成单键按压、且按压时长受限的玩家提供完整可游玩路径。入口在右上角
♿ 图标，启用后右下角出现单键控制台。

### 玩家填写的能力参数

- 能完成的按压时长范围（短按/长按阈值与灰区由求解器据此推导）
- 反应延迟（看到提示到开始动作）
- 每个手势最多按几次
- 提竿窗口允许延长的上限
- 扫描驻留时长，以及自动提竿 / 自动缓线 / 峰值自动抛竿开关
- 已熟悉的手势映射可以锁定，重新求解时保持不变

### 求解规则（`src/features/assist/model/solver.ts`）

- 手势 = 短按(S)/长按(L)序列，按分组（湖畔、钓点、鱼饵、鱼获、挑战）分配，
  同一时刻只有一个分组激活，组内手势互不重复。
- 风险动作（抛竿扣饵、放流、领奖）的一次漏按 / 多按 / 长短翻转邻域，
  不允许落在任何已分配手势上；无解时明确列出冲突，而不是拒绝全部输入。
- 多长度码之间用静默等待分隔，**该等待计入对应手势的最坏响应时间**，
  预览中逐动作展示最坏耗时与全局最坏响应。
- 提竿预算 = 反应延迟 + 提竿手势最坏耗时；需要的窗口延长不得超过玩家上限，
  延长写入游戏规则（`assistStrikeExt`），不会无限等待，也不改变鱼的冲刺节奏。
- 松线 5 秒脱钩、蓄力周期等硬约束同样参与可行性检查。

### 识别器（`src/features/assist/model/recognizer.ts`）

- 落入短按/长按灰区、序列无法成为任何手势前缀、间隔超时均判为误触并提示重试，
  绝不猜测成另一个动作；无错误的手势必定可靠识别。
- 风险动作识别成功后进入二次确认：再做一次相同手势才执行，
  识别成其他手势则取消。
- 鼠标与空格/回车走同一个物理单键通道，一次按压只提交一次；
  窗口失焦或阶段切换会清除未完成输入并停止收线。
- 已扣饵、已放流、已领奖的结果不可通过改判撤销。

### 验证

- `npm run verify:assist`：手势编码、求解约束、识别器安全性（33 项）
- `npx tsx scripts/verify-integration.ts`：提竿延长、自动抛竿/缓线、
  不可撤销与本地存取的游戏模型集成（23 项）
